## Scores

**Proposal A (brief-first) — 8/10.**
Best spine of the three. The tier-first ranking is the single strongest idea in the whole panel: a blended score would let a fresh media-queue item outrank a two-day-old backup failure, and A is the only proposal that refuses to blend, ranking by tier and breaking ties by age. Its phase 1 is also the only one honestly sized for one session, and it correctly identifies that the fake `setInterval` agent-sim is welded to the flat `view` router so killing one kills the other. Best idea: tier-first ranking with "+N more" collapse instead of a wall. Worst blind spot: it starves the RFI purpose. The brief asks for a live log with *answer state*, and A ships read-only through phase 2 with the write path deferred to an unscheduled investigation, which means the one workspace Jake actively maintained yesterday (job 119, revised 8/22) stays a read-only mirror of a markdown file. Second, factually wrong on the media write path. It proposes adding a `POST /api/decide` endpoint to `photo-gallery.py`; the gallery already exposes `/toss`, `/keep`, `/record`, `/tag`, `/untag`, `/undo`, `/collect`, `/mark-posted`. A would have built a second writer while arguing against second writers. Third, folding Costs/Intelligence into a digest sourced from `brief-<today>.md` ignores the audit's own finding that today's file did not exist at audit time; a morning-check-in surface cannot depend on a file that does not exist in the morning.

**Proposal B (workspace-first) — 8/10.**
Serves all four purposes most evenly and is by far the strongest on the thing the brief actually calls SOTA: keyboard-fast working surfaces. The `j/k` + `1-5` + `x` + `/` contact-sheet map, `Cmd+K` as the one place "keyboard-fast" lives, chokidar-watched `rfi.json` pushing over a topic-tagged WS, and inline `1-4` status changes are concrete interaction design where the others wrote nav trees. It is also the most epistemically honest proposal, the only one that says "verify first whether photo-gallery.py exposes its own write routes and proxy to those" (it does) and "verify the firewall actually restricts :3080, don't assume." Best idea: the whole Media/RFI interaction layer plus WS topic tags. Worst blind spot: `surfaced_penalty`. Decaying an item's rank each time it is shown without action makes the queue quietly hide exactly the items Jake keeps dodging, and the items he dodges are blocking RFIs and pay apps, the expensive ones. That is a ranking function that optimizes for a tidy screen over a correct one. Secondary: phase 1 is overstuffed (auth plus router plus `/api/brief` plus RFI read *and* write plus media embed) and would not land in one session; and folding Projects into `/jobs/:id` is wrong on the facts, since `projects.json` holds AI-OS work streams like "Live RFI" that do not map to JobTread jobs at all.

**Proposal C (trust-first) — 7/10.**
Wins the client view outright and it is not close. Every other proposal makes the client API a filtered view over internal data; C makes it a precomputed projection file with an endpoint that takes no id argument at all, so there is no code path that can accept a caller-supplied job id and therefore no IDOR to write. "The page cannot leak what it was never handed" is the correct security posture for the one surface a client sees. Its Systems table is also the best of the three, checking artifact age and byte size rather than liveness, and it is the only one that flags the 0-byte `tc-backup.log` as a red card today. Best idea: the snapshot projection. Worst blind spot: it is thinnest exactly where Jake works daily. Media is an iframe plus a generate strip, RFI writes slip to phase 3, and the command palette is deleted in phase 1 to be rebuilt in phase 3, which is pure churn. It also asserts `rc-brand-config.json` does not exist and must be created; it exists at `~/services/tread-connection/rc-brand-config.json` and has since April. A trust-first proposal that gets a checkable fact wrong about the file it wants to author is a warning about the rest of its unverified assertions.

**Base structure taken:** A's spine (IA, tier-first Brief, phasing). **Grafted:** B's workspace interaction design and WS topics, C's client projection and Systems outcomes table.
